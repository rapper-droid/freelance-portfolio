# EXPERIMENTS — 配布実験の台帳

更新: 2026-09-20

**仮説 → 準備 → 配布 → 観測 → 結果**を分けて記録する。準備しただけの状態を
「実施」と書かない。反応は、実際に公開・送信したものについてだけ数える。

判断: `continue`（続ける） / `change`（変える） / `pause`（止める） /
`insufficient_data`（データ不足）。

---

## EXP-01 — 公開協業募集への個別提案（W01 / 制作パートナー）

| 項目                 | 内容                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仮説                 | 実装パートナーを公募している制作会社には、「表示崩れの修正1か所」のような**範囲の決まった小さな作業**と実物のサンプルを示すと、返信が得られやすい |
| 対象                 | 公式に協業・業務委託先を募集している事業者。募集範囲と受付方法が公開されているもの                                                                |
| 商品                 | W01（＋条件が合えば W02）                                                                                                                         |
| 根拠として見せるもの | `/partners`（対応範囲・受け渡し・検収・守秘）、`/demos/improvement`                                                                               |
| 経路                 | 募集で指定された受付方法（フォーム／指定アドレス）。Resend は使わない                                                                             |
| 着地                 | `/partners`（`#brief` で条件整理）                                                                                                                |
| 原稿                 | `artifacts/growth-public/listings/partners/collab-outreach.md`（テンプレート）                                                                    |
| 準備の状態           | **未配布**。宛先0件（候補調査が未実施）                                                                                                           |
| 観測する数           | 調査数 / 適合数 / 送信数 / 返信数 / 仕様相談に進んだ数 / 見積数。**すべて別々に数える**                                                           |
| 観測期間             | 送信日から14日（返信なし＝失注とは扱わない）                                                                                                      |
| 制約                 | 母数が小さい。返信率を比較しない                                                                                                                  |
| 次の判断             | `insufficient_data`（未配布のため）                                                                                                               |

## 記録の様式（実施したら追記する）

```text
experiment_id / hypothesis / audience / offer_id / evidence_ids
channel / permitted_destination / landing_route / primary_action
asset_revision / approval_state / published_or_sent_at
measurement_source / observation_window / outcome / limitations
next_decision: continue | change | pause | insufficient_data
```

## いま言えないこと

- どちらの実験も**まだ配布していない**ため、反応は0ではなく「未観測」。
- 少数のデータで「成功率」「最適化完了」と書かない。改善前後を比べるときは
  期間と母数を必ず併記する。
