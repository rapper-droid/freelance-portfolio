## 2. 実写ストック写真を導入しなかった理由

指示書は「必要なら実写参考写真を導入」とし、条件として

```text
商用利用可能 / 出典が追跡可能 / ライセンス上問題なし / watermarkなし
```

を挙げています。**この条件を満たせることを確認できなかったため、導入していません。**

確認した内容:

```text
images.unsplash.com    到達可能（画像の配信のみ）
unsplash.com の検索     空レスポンス。写真IDと撮影者を列挙できない
api.unsplash.com       APIキーが必要（新規登録が発生する）
```

つまり **写真の実体は取得できても、その1枚の撮影者・ライセンス・利用条件を
記録できる状態にできませんでした。**

出典を確認せずに実在の写真を載せると、
**実際に仕事を受けている稼働サイトに、検証していない権利リスクを持ち込む**ことになります。
出典を推測で書くことは、それ以上に良くありません。

AI画像生成による代替も行っていません。追加クレジットを消費するためです。

### 代わりにしたこと

商品画像は **サイト内でSVGとして描いています**（`src/components/cafe-art.tsx`）。

- 架空の店舗なので、そもそも撮影対象が存在しない
- 6種類の飲み物が同じ線の太さ・同じ器の家族で揃う
- 実在する6つの別々のカフェの写真を混ぜるより、統一感が出る
- responsive / crisp / 軽量 / 色は親要素から継承

アクセスの地図も同じ考えで概略図にしています。架空店舗に実在の地図を出すと、
無関係な住所を指してしまうためです。

## 3. 本人が実写を入れる場合（NEEDS_OWNER_DECISION）

実写を入れる判断をされる場合、以下を満たす素材をご用意ください。

```text
候補      Unsplash / Pexels（いずれも商用利用可・帰属表示不要）
          または撮影実費のないご自身の撮影素材
必要情報   写真ページのURL / 撮影者名 / ライセンス名 / 取得日
禁止      watermark入り / ライセンス不明 / 出典を追跡できないもの
```

差し替え先は以下です。SVGを消さずに、写真がある項目だけ差し替えられます。

```text
public/visuals/          店舗・商品写真
src/lib/cafe-menu.ts     各メニューの art を photo パスへ変更する形に拡張
```

取得後は**この表に1行ずつ追記**してください。
出典が書けない画像は載せない、という運用を保つためのファイルです。
