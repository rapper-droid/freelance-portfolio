# TANEBI WORKS — ART DIRECTION

視覚表現の判断基準です。**素材を増やす前にここを決めています。**

優先順位:

```text
理解しやすさ  >  信用  >  TANEBIらしさ  >  演出
```

仕事を受けるサイトなので、**装飾より理解と信頼が先**です。
TANEBIらしさは残しますが、ゲームUIにはしません。

---

## 1. 色

すべて MASTER BRAND ICON からの実測値です（`docs/BRAND_ICON.md`）。

```text
地          #0e0906   マークの地色そのもの
深い面      #090300   ヒーローなど一段沈む面
インク      #f0e9e0   本文（15:1）
補助        #c2b7aa   補足（10:1）
accent      #fcbe69   ember。1色だけ（11.6:1）
罫線        #332c26
```

**accentは1色**です。HQが暖色accentを1つだけ持つ構造を共有しています。
複数の強調色を持たせると、どれが重要か分からなくなります。

## 2. 余白とリズム

```text
セクション縦    clamp(64px, 7.2vw, 104px)
セクション横    60px（狭い画面では 25px）
カード内側      18–24px
図の上          28–34px
本文行間        1.75–1.95
```

デモ内（`.cafe-demo` など）は**その作品自身の余白**を持ちます。
作品の一部なので、WORKS のリズムを上書きしません。

---

## 3. 面・枠・角丸

```text
角丸    カード 14px / 小要素 8–10px / ボタン 8px / タグ 999px
枠      1px solid var(--hub-border)
面      color-mix(in srgb, var(--hub-ink) 4%, transparent)
```

**「枠だけ」をやめて「面」を持たせる**のが、資料っぽさから抜ける一番効く変更でした。
「依頼から納品まで」の再設計はこれが主因です。

影は原則使いません。暗い地では効かず、代わりに面の明度差で階層を作ります。

## 4. 4種類のビジュアルと役割

| 種類               | 使う場所                            | 実装                                     |
| ------------------ | ----------------------------------- | ---------------------------------------- |
| **ネイティブ図解** | 工程・自動化・API・QA・Before/After | 意味のあるHTML＋CSS。SVGは装飾のみ       |
| **キービジュアル** | カテゴリの世界観                    | `scripts/generate-keyvisuals.mjs` で生成 |
| **商品アート**     | カフェのメニュー                    | `src/components/cafe-art.tsx` のSVG      |
| **UIモック・写真** | 制作例・店舗                        | 既存のスクリーンショットとAI生成画像     |

### 図解を画像にしない

工程図・比較図は**画像ではなくHTML**です（`ol` / `dl` / `figure`）。
CSSを外しても、読み上げでも、情報が残ります。
**説明文を1枚の画像に焼き込むことはしていません。**

### キービジュアルの文法

12カテゴリすべて同じ構成で生成しています。

```text
地          #0e0906
光源        右上から ember が1つ
モチーフ    暖色の線画・低不透明度
粒状        わずかなノイズ（暗部のバンディング防止）
下端        地の色へフェード
```

**見出しと競合させない**ため、不透明度は 0.55（モバイル 0.4）、
下端をマスクで消し、文字は常に地色に対して 15:1 以上を保っています。
実測: 見出し 17.02:1 / リード 10.39:1。

12枚あわせて **36KB**（写真1枚より軽い）。すべて `aria-hidden` ＋ 空alt の装飾で、
カテゴリ名は画像の上に**テキストとして**必ず存在します。

## 5. ember演出の強さ

```text
使う    現在地・押した結果・工程の進行・依頼者が確認する場面
使わない 常時光るもの・意味のない発光・全画面エフェクト
```

Primary CTA だけが点火します。全ボタンが光るとブランド効果が消えます。
詳細は `docs/TANEBI_EFFECTS.md`。

## 6. 画像を入れる基準

入れてよいのは次のいずれかを**実際に**満たす場合だけです。

```text
理解しやすくなる / 完成イメージが伝わる / 依頼したくなる / 信用感が上がる
```

入れないもの:

```text
意味のないstock写真 / 無意味な背景画像 / 統一感のない寄せ集め
重くなるだけの大画像 / 文字が読みにくくなる背景 / CTAが弱くなる構成
```

## 7. 技術条件（全ビジュアル共通）

```text
responsive      幅で密度を変える。情報とCTAは変えない
CLS             高さを必ず予約する（aspect-ratio か固定height）
lazy loading    ファーストビュー以外は lazy
alt             意味のある画像は説明。装飾は空alt＋aria-hidden
contrast        本文 4.5:1 以上。実測は 10:1 以上
性能            transform / opacity 中心。canvas・動画背景は使わない
```

CLSについては、`aspect-ratio` と `max-height` を併用すると
**幅が高さから逆算されて縮む**ことがあります（カテゴリ帯で実際に起きました）。
高さは明示し、幅は 100% を優先します。
