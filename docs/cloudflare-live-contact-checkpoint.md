and Resend responses are intercepted only in this isolated fixture environment.
Sixteen scenarios pass: stable-ID retry, payload conflict, per-IP rate limit,
daily/monthly send caps, same-receipt deduplication, concurrent attempts, storage
outage, wrong action/hostname, absent/invalid/replayed tokens, provider timeout /
5xx / rejection, preview origin, and partial automatic-reply failure.

The separate native state suite passes six baseline cases and detects all four
intentional mutations, including expiry, NX, unlock-token, and counter faults.
Short locks, TTL, counters, and duplicate suppression are therefore tested in a
real isolated Workers engine. Only the per-client rate limit was additionally
proven on the deployed namespace. No storage fault was injected there and no
global daily/monthly quotas were exhausted.

Partial reply behavior: owner acceptance is retained; the UI says the inquiry
is accepted but its confirmation mail is still unsent. Retry targets only the
confirmation; it does not resend the owner mail. This remains controlled-test
evidence until a live failure scenario can be safely exercised.
